1. Overview

The FSK Decoder tab provides real-time UDP packet capture, decoding, and logging capabilities for FSK (Frequency-Shift Keying) modulated data streams. This document details all technical implementation aspects including threading architecture, memory management, data flow, and performance characteristics.

1.1. Key Features

  • Real-time UDP packet reception on port 9000

  • Multi-threaded architecture for high-throughput processing

  • Dual-mode operation: Normal FSK decoding and Test mode

  • Configurable file logging (.log and .csv formats)

  • Live UI updates with packet preview

  • Robust packet loss detection and reporting

  • Buffer overflow protection with queue management

3.2. Thread 1: Receive Thread (_listen)

File Location: [udp_fsk.py:136-175](src/udp_fsk.py#L136-L175)

3.2.1. Responsibilities

  • Bind and listen on UDP port 9000

  • Receive incoming packets (up to 65535 bytes)

  • Timestamp packets with nanosecond precision

  • Enqueue packets for processing

  • Monitor queue overflow conditions

3.2.2. Implementation Details

Thread Type: daemon=True
Socket Type: SOCK_DGRAM (UDP)
Bind Address: 0.0.0.0:9000
Socket Timeout: 1.0 second
Receive Buffer: 65535 bytes per call

3.2.3. Data Flow

  1. Socket Setup

    • Creates UDP socket with SO_REUSEADDR option

    • Sets receive buffer size to 8 MB (configurable)

    • Binds to all interfaces on port 9000

    • Sets 1-second timeout for graceful shutdown

  2. Receive Loop

    • Continuously calls recvfrom(65535)

    • Captures high-precision timestamp: time.time_ns()

    • Attempts non-blocking queue insertion

    • Handles timeout exceptions for clean shutdown

  3. Overflow Handling

    • When queue is full, increments _queue_dropped_packets

    • Logs error every 1st and 100th dropped packet

    • Does NOT block - packet is discarded immediately

3.3. Thread 2: Process Thread (_process_packets)

File Location: [udp_fsk.py:177-224](src/udp_fsk.py#L177-L224)

3.3.1. Responsibilities

  • Dequeue packets from the internal queue

  • Decode FSK packet headers and records

  • Detect and report packet loss

  • Write to log files (.log and .csv)

  • Invoke UI callback with packet preview

  • Periodic flushing of buffers

3.3.2. Implementation Details

Thread Type: daemon=True
Queue Get Timeout: 0.5 seconds
Processing Rate: Continuous until queue empty
Flush Interval: Every 250 packets
Queue Monitoring: Every 250 packets

3.3.3. Processing Loop

  1. Dequeue Phase

    • Blocks up to 0.5 seconds waiting for packets

    • Retrieves tuple: (timestamp_ns, raw_bytes)

    • Continues even after _running=False to drain queue

  2. Decode Phase

    • Validates packet magic number (0x314B5346)

    • Extracts header: sequence, record count, version

    • Decodes individual records (normal or test mode)

    • Detects sequence gaps for packet loss calculation

  3. Logging Phase

    • Writes hex preview to .log file (if enabled)

    • Appends decoded records to CSV batch buffer

    • Batch size: 20,000 lines before flush

  4. UI Update Phase

    • Formats preview records (limited to first 3)

    • Calls on_packet() callback on UI thread

    • Non-blocking - exceptions are silently caught

  5. Periodic Maintenance (every 250 packets)

    • Flushes CSV batch buffer to disk

    • Flushes log file buffer

    • Checks queue depth and warns if >10% full

    • Implements hysteresis to prevent log spam

3.4. Thread 3: UI Thread (Main)

File Location: [app.py:880-984](src/app.py#L880-L984)

3.4.1. Responsibilities

  • Render FSK tab interface

  • Handle Start/Stop button clicks

  • Display real-time packet summaries

  • Update status indicators

3.4.2. UI Update Mechanism

Cross-Thread Communication:

  1. Process thread calls self._on_packet(seq, rec_count, preview_records)

  2. Callback is defined in app.py as _fsk_on_packet()

  3. Callback DOES NOT update UI directly

  4. Instead, it enqueues message: self.ui_q.put"fsk", (seq, rec_count, preview_records)

  5. Main UI loop polls ui_q periodically

  6. UI updates are performed only on the main thread

Thread Safety Approach: Queue-based message passing (no locks needed for UI updates)

3.4.3. UI Refresh Rate

UI Queue: queue.Queue (thread-safe)
Polling Interval: ~100ms (typical Tkinter event loop)
Display Throttling: All packets shown (no throttling currently)
Text Widget State: DISABLED (read-only display)

6. Queue and Buffer Configuration

6.1. Packet Queue

File Location: [udp_fsk.py:79](src/udp_fsk.py#L79)

Queue Type: queue.Queue (thread-safe FIFO)
Max Size: 10,000 packets (configurable via queue_size parameter)
Item Format: tuple[int, bytes]  # (timestamp_ns, raw_packet_data)
Overflow Handling: put_nowait() → raises queue.Full → packet dropped

6.1.1. Queue Sizing Rationale

  • 10,000 packets provides ~10 seconds of buffering at 1000 pps

  • Allows Process thread to catch up during brief CPU spikes

  • Prevents memory exhaustion under sustained overload

  • Warning threshold: 10% full (1,000 packets)

6.1.2. Queue Monitoring

Check Frequency: Every 250 packets
Warning Threshold: max(100, queue_size // 10)  # 1,000 for default
Hysteresis: Bucketized warnings (0-9) to prevent spam
Status: Logged as [WARN] with depth ratio

6.2. CSV Batch Buffer

File Location: [udp_fsk.py:85-86](src/udp_fsk.py#L85-L86)

Type: list[str]
Max Size: 20,000 lines (configurable via _csv_batch_size)
Flush Triggers:
  - Batch reaches 20,000 lines
  - Every 250 packets processed
  - On stop() call (final flush)
Line Format: CSV row as pre-formatted string

6.2.1. Batch Buffer Rationale

  • Reduce I/O syscalls: 20,000 lines written in single operation

  • Improved throughput: ~100× reduction in write calls

  • Memory trade-off: ~2 MB buffer vs. frequent disk seeks

  • Flush interval: Ensures data persisted every 250 packets (~0.5 sec at 500 pps)

6.3. File Buffers

Log File (.log):
  - Buffer Size: 1 MB (1024 * 1024 bytes)
  - Mode: Append ("a")
  - Encoding: UTF-8
  - Flush: Every 250 packets

CSV File (.csv):
  - Buffer Size: 1 MB (1024 * 1024 bytes)
  - Mode: Write/Append ("w" on init, then writes)
  - Encoding: UTF-8
  - Newline: "" (universal newlines)
  - Flush: Every 250 packets + batch buffer flush

7.3. Thread-Safe Logging

7.3.1. Log File Thread Safety

File Location: [udp_fsk.py:368-373](src/udp_fsk.py#L368-L373)

def _log(self, text: str) -> None:
    if not self._enable_log_file or not self._log_file:
        return
    with self._log_lock:  # <--- Critical section
        if self._log_file:
            self._log_file.write(text)

  • Lock: threading.Lock() instance

  • Scope: Single write operation

  • Contention: None (only Process thread writes)

7.3.2. CSV File Thread Safety

File Location: [udp_fsk.py:392-402](src/udp_fsk.py#L392-L402)

def _flush_csv_batch(self) -> None:
    if not self._csv_batch_buffer or not self._csv_file:
        return
    try:
        with self._csv_lock:  # <--- Critical section
            if self._csv_file:
                self._csv_file.writelines(self._csv_batch_buffer)
                self._csv_batch_buffer.clear()
    except (PermissionError, AttributeError):
        pass

  • Lock: threading.Lock() instance

  • Scope: Batch write + buffer clear

  • Contention: None (only Process thread writes)

7.3.3. Why Locks Are Needed

Even though only the Process thread writes to files, locks protect against:

  1. Shutdown races: Stop() called while write in progress

  2. File handle closure: Ensure write completes before file closed

  3. Future-proofing: If multi-threaded processing is added later

8.2. Decoding Process

8.2.1. Step 1: Header Validation

File Location: [udp_fsk.py:226-234](src/udp_fsk.py#L226-L234)

1. Check minimum packet size (>= 20 bytes)
2. Unpack header using struct.unpack_from()
3. Validate magic number == 0x314B5346
4. If invalid: Log warning, discard packet

8.2.2. Step 2: Sequence Tracking

File Location: [udp_fsk.py:236-251](src/udp_fsk.py#L236-L251)

1. Retrieve last sequence number (_last_seq)
2. Calculate expected sequence: last_seq + 1 (with optional wraparound)
3. If gap detected:
   - Calculate packets lost
   - Increment _total_packets_lost
   - Log [PACKET LOSS] event with percentage
4. Update _last_seq = current sequence

Sequence Wrapping: Configurable via sequence_wrap_at parameter (default: None = 2^32-1)

8.2.3. Step 3: Record Decoding

File Location: [udp_fsk.py:278-323](src/udp_fsk.py#L278-L323) (Normal) [udp_fsk.py:324-366](src/udp_fsk.py#L324-L366) (Test)

FOR each record (0 to rec_count-1):
  1. Check offset + record_size <= packet length
  2. Unpack record using struct.unpack_from()
  3. Extract bit flags (toggled, valid_transition, etc.)
  4. If i < ui_record_limit: Add to preview_records[]
  5. Format CSV row string
  6. Append to csv_rows[] list
  NEXT record

7. Batch append csv_rows to _csv_batch_buffer
8. Return preview_records for UI callback

Performance Note: CSV rows are pre-formatted as strings to avoid repeated formatting overhead.

1. Process Thread: _fsk_on_packet() called with (seq, rec_count, preview_records)

3. Main UI Loop: Polls ui_q every ~100ms
4. UI Handler: Formats packet summary, appends to Text widget
5. Text Widget: Scrolls to end, updates status label

9.2. Thread-Safe UI Updates

CRITICAL RULE: Never update Tkinter widgets from background threads

9.2.1. Implementation

File Location: [app.py:917-919](src/app.py#L917-L919)

def _fsk_on_packet(self, seq: int, rec_count: int, preview_records: list):
    """Called from FSKReceiver thread — schedule UI update."""
    self.ui_q.put(("fsk", (seq, rec_count, preview_records)))

  • No direct UI access: Callback only enqueues data

  • Thread-safe queue: queue.Queue handles synchronization

  • Main thread polls: UI updates happen on Tkinter thread

  • Exception handling: Process thread catches all callback exceptions

9.3. UI Performance Considerations

9.3.1. Text Widget Limitations

  • Unbounded growth: Text widget accumulates all packets

  • Memory leak: Long captures can consume gigabytes

  • Scroll performance: Degrades with >10,000 lines

9.3.2. Recommended Improvements

  1. Line limit: Implement rolling buffer (keep last N lines)

  2. Throttling: Update UI every N packets instead of every packet

  3. Pause/Resume: Allow user to pause UI updates while capture continues

11.1. Packet Loss Detection

File Location: [udp_fsk.py:238-250](src/udp_fsk.py#L238-L250)

11.1.1. Mechanism

  1. Sequence Tracking: Each packet has incrementing sequence number

  2. Gap Detection: Compare received sequence to expected (last + 1)

  3. Loss Calculation: Handle wraparound with modular arithmetic

  4. Reporting: Log [PACKET LOSS] with count and cumulative percentage

11.2. Queue Overflow Protection

File Location: [udp_fsk.py:164-172](src/udp_fsk.py#L164-L172)

11.2.1. Mechanism

  1. Non-Blocking Insert: queue.put_nowait() raises queue.Full

  2. Exception Catch: Increment _queue_dropped_packets counter

  3. Throttled Logging: Log every 1st and 100th dropped packet

  4. No Crash: Packet is discarded, system continues

11.3.1. Mechanism

  1. Periodic Check: Every 250 packets processed

  2. Warning Threshold: 10% of queue_size (1,000 for default)

  1. Set Flag: _running = False

  5. Close Files: Flush and close log/CSV file handles

12. Performance Tuning Guide

12.1. Optimizing for High Throughput

12.1.1. 1. Disable .log File

Impact: Reduces I/O by ~80% (only CSV writes remain)

UI: Uncheck "Log to .log file"
Code: enable_log_file=False

12.1.2. 2. Increase Queue Size

Impact: More buffering during processing spikes

Default: queue_size=10000
High-throughput: queue_size=50000
Trade-off: ~50 MB more RAM

12.1.3. 3. Increase CSV Batch Size

Impact: Fewer disk writes, higher latency

Default: _csv_batch_size=20000
High-throughput: _csv_batch_size=100000
Trade-off: ~10 MB more RAM, data delayed up to 5 seconds

12.1.4. 4. Reduce UI Updates

Impact: Less main thread contention

Default: ui_record_limit=3
Performance: ui_record_limit=0  (disable UI previews)

13. Troubleshooting

13.1. Common Issues

13.1.1. Issue: Queue Depth Warnings

Symptom: Frequent [WARN] messages about queue depth

Cause: Process thread cannot keep up with packet rate

Solutions:

  1. Disable .log file (reduces I/O)

  2. Increase queue_size (more buffering)

  3. Reduce ui_record_limit to 0 (disable UI previews)

  4. Check disk speed (upgrade to SSD)

  5. Close other CPU-intensive applications

13.1.2. Issue: Dropped Packets

Symptom: [ERROR] messages about queue full

Cause: Queue overflow, packet rate exceeds processing capacity

Solutions:

  1. Apply all high-throughput optimizations above

  2. Increase socket_buffer_size (more kernel buffering)

  3. Consider multi-threaded processing (requires code changes)

13.1.3. Issue: Packet Loss Detected

Symptom: [PACKET LOSS] messages in log

Cause: Network issues, sender side buffer overflow

Solutions:

  1. Check network stability (ping, iperf)

  2. Increase sender-side UDP buffer

  3. Reduce packet send rate at source

  4. Use wired connection instead of WiFi

13.1.4. Issue: High Memory Usage

Symptom: Application using >500 MB RAM

Cause: Unbounded Text widget growth in UI

Solutions:

  1. Restart application to clear UI buffer

  2. Implement line limit in _fsk_append_batch() (code change needed)

  3. Use ui_record_limit=0 to disable UI updates

13.1.5. Issue: CSV File Not Created

Symptom: No fsk_data.csv in logs/fsk/ directory

Cause: CSV logging disabled, or file permission error

Solutions:

  1. Ensure "Log to .csv file" checkbox is checked

  2. Check logs/fsk/ directory exists and is writable

  3. Check log file for [WARN] permission errors
